# ТЗ: учёт исполнительной геодезической документации на доске FreeWrite

**Версия 1 — проект для согласования с Владимиром (11.11.2026).**
Собрано из описания Владимира, ТЗ от ChatGPT, таблицы Excel Владимира (лист на раздел + «Статистика») и ответов
Владимира на 10 вопросов. Пока ТЗ не согласовано, код по нему не пишется.

---

## 0. Зачем

Сейчас геодезист пишет одно и то же в нескольких местах: у чертежа (захватки, наличие схем), в списках «что отдал на
подпись / что вернули», потом сводит всё в Excel. Через несколько дней записи расходятся и непонятно, что сдано, а что нет.

**Главный принцип:** каждая схема ИГС хранится **в одном месте**. Таблица у чертежа, ведомость передачи, подсветка
захватки на плане, сводка — только разные «окна» на одни и те же записи. Поменяли статус в одном окне — он поменялся
везде. Ничего не переписывается вручную дважды.

## 1. Что уже есть и не ломается

- Рукописный ввод (Запись, «В текст» на доске), доска: картинки и листы PDF, заливки, разделы, метки, выноски, фигуры,
  импорт из Nebo — всё остаётся как есть.
- Общая доска на сервере в Яндекс Облаке (бесплатные лимиты), правки расходятся за несколько секунд; код на правку и
  код «только смотреть»; сайт для просмотра с компьютера.
- Статусы конструкций (выноски) остаются. Список статусов ИД заменяется новым списком ИГС (раздел 4).
- Старые «строки ИД» (0.18) переносятся в новые таблицы кнопкой «В таблицу» — ничего не теряется.

## 2. Основные понятия

| Понятие | Что это | Как выглядит |
|---|---|---|
| **Объект** | Одна доска = один строительный объект | Доска в Ежедневнике |
| **Раздел** | Часть проекта: монолитный каркас, кладка, сети, благоустройство, корпус, этаж | Рамка раздела на доске (уже есть) |
| **Таблица ИД** | Все схемы одного шифра проекта («КЖ 6.1.1», «КЖ4 Лотки») | Таблица рядом с план-схемой |
| **Схема** | Одна исполнительная схема = одна строка таблицы | Строка: захватка/участок, конструкция, вид работ, статусы, даты |
| **Ведомость** | Пачка схем, которую отдают АН, заказчику или в ПТО | Отдельная табличка в любом месте доски |
| **Захватка на плане** | Закрашенная область на план-схеме, привязанная к захватке таблицы | Заливка (уже есть) |
| **История** | Кто, когда и что поменял у схемы | Окно «История» у строки |

**Одна строка = одна схема.** Если на одну работу нужно несколько схем — работа дробится на захватки или участки
(как сейчас в Excel). Признак «та же схема»: таблица (шифр) + захватка/участок + конструкция + вид работ;
повтор в одной таблице — предупреждение.

## 3. Таблица ИД

### 3.1. Вид
- Шапка: **шифр** (крупно) и сводка в одну строку: «54 схемы · сдано в ПТО 39».
- Строка с названиями столбцов, ниже строки схем. **Все строки одного размера и ровно по столбцам**; ширина столбца — по
  самому длинному значению. Размер задаётся один на всю таблицу; новая таблица — того же размера, что уже стоящие на доске.
- Таблица двигается и масштабируется целиком (как картинка), переносится вместе со своим разделом.
- Издалека — рамка и цветные полоски статуса ИГС (видно, где «горит», без надписей).

### 3.2. Столбцы — настраиваемые
По умолчанию (порядок как в Excel Владимира):

| Столбец | Что | Ввод |
|---|---|---|
| Захватка | Номер захватки или участка: «5», «5.1», «Захватка №1 (6-7/А-Е)», «Лоток №1», «19-21/А» | Текст |
| Конструкция | Тип конструкции: «Вертикал», «Парапет», «Плита пола Пм1» | Текст с подсказками из уже введённого |
| Вид работ | «Опалубка», «Бетон», «Разработка», «Обратная засыпка», «Кладка», «Монтаж»… | Выбор из списка или текст |
| Дата работ | Дата бетонирования / выполнения работ | Календарь |
| Чек-лист | Статус чек-листа (раздел 4.2) | Касание — список |
| DWG | Статус DWG (раздел 4.3) | Касание — список |
| ИГС | Статус схемы (раздел 4.1) | Касание — список |
| Отдал заказчику | Дата, когда схему отдали заказчику на подпись | Ставится ведомостью, можно поправить |
| Сдано в ПТО | Дата, когда схему сдали в ПТО | Ставится ведомостью, можно поправить |
| Исполнитель | Подрядчик: «АР-Старт», «СТЭП», «МС22», «СС» | Текст с подсказками |
| Примечание | Любой текст: «вопрос у ПТО по объёму (9.1)» | Текст |

Настройка таблицы:
- переименовать столбец (например, «Захватка» → «Участок» для лотков и сетей);
- скрыть / показать столбец;
- добавить свой текстовый столбец (для другого объекта: «Секция», «Этаж», «Оси»);
- взять столбцы «как у таблицы …» (чтобы не настраивать каждую заново).

### 3.3. Заполнение
- Статус (Чек-лист, DWG, ИГС): касание ячейки → короткий список статусов с цветами → выбор.
- Текст: касание ячейки → поле с подсказками (что уже встречается в этом столбце) и кнопками частых значений;
  писать можно **пером** (распознавание, как «В текст») или клавиатурой.
- Дата: календарь, кнопка «Сегодня», «Без даты».
- «+ строка» внизу таблицы — форма всей строки сразу; в ней кнопки видов работ можно отметить несколько
  («Опалубка» + «Бетон») — появится по строке на каждый.
- «+ Следующая захватка» — номер +1, конструкция и исполнитель как у предыдущей, статусы — начальные.
- Подержать строку — меню: изменить строку, история, строка ниже, вверх/вниз, в ведомость, удалить.
- «Конструкция не выполнена» — одной кнопкой: Чек-лист, DWG и ИГС = «Не выполнено».
- Отбор и поиск: показать в таблице только строки со статусом / исполнителем / текстом (остальное скрыто до «Показать всё»).

## 4. Статусы

Порядок работы: сначала сдаём конструкцию и готовим чек-лист; когда чек-лист подписан — готовим схему.
Названия и цвета можно поправить в «Статусах»; ниже — начальные списки (от Владимира).

### 4.1. ИГС (схема)

| Статус | Смысл | Цвет |
|---|---|---|
| Не выполнено | Конструкция не возведена | серый |
| Не предоставлена | Не понимаем, что со схемой | красный |
| В работе | Схема делается | синий |
| На подписи АН | Нужно согласование авторского надзора (отклонения сверх допуска) | фиолетовый |
| Не согласована | АН не согласовал отклонения — нужно решение | тёмно-красный |
| На подписи у заказчика | Унесли на подпись | жёлтый |
| Возврат на корректировку | Заказчик или АН выявили замечания | оранжевый |
| Сдано в ПТО | Схему отдали в ПТО — **это и есть «сдано»** | зелёный |

### 4.2. Чек-лист

| Статус | Смысл | Цвет |
|---|---|---|
| Не выполнено | Конструкция не выполнена | серый |
| Не предъявлено | Конструкция возведена, но её не предъявили | красный |
| Нет возможности предъявить | Конструкцию загромоздили — освидетельствовать нельзя | оранжевый |
| Предъявлено | Есть чек-лист, подписанный заказчиком | зелёный |

### 4.3. DWG

| Статус | Цвет |
|---|---|
| Не выполнено | серый |
| Нет | красный |
| Есть | зелёный |

### 4.4. Подсказки (не запреты)
- Схема «В работе» или дальше, а чек-лист не «Предъявлено» — строка помечается, попадает в «Контроль» (раздел 9).
- Файлы (DWG, PDF, сканы) в приложение **не загружаются** — только статусы (не грузим сервер).

## 5. Даты по схеме
- **Дата работ** — вводится вручную.
- **Отдал заказчику** — ставится сама при передаче ведомости заказчику (дата передачи), можно поправить вручную.
- **Сдано в ПТО** — ставится сама при сдаче в ПТО, можно поправить вручную.
- Остальные даты (передал АН, вернули с замечаниями) видны в истории схемы и в ведомостях.

## 6. Ведомости

### 6.1. Виды

| Вид | При передаче схемам ставится | Результаты по каждой схеме |
|---|---|---|
| На согласование АН | ИГС «На подписи АН» | «Согласовано» → статус (см. вопрос 1) · «Не согласовано» → «Не согласована» · «Замечания» → «Возврат на корректировку» |
| На подпись заказчику | ИГС «На подписи у заказчика», дата «Отдал заказчику» | «Подписано» → «Сдано в ПТО» + дата (см. вопрос 2) · «Замечания» → «Возврат на корректировку» |
| Сдача в ПТО | ИГС «Сдано в ПТО», дата «Сдано в ПТО» | — (закрывается сразу) |
| Список | Ничего (просто список: «что делать завтра», «что проверить») | — |

### 6.2. Как живёт ведомость
1. **Черновик.** Создали ведомость в любом месте доски («На подпись заказчику», номер ставится сам: «З-12»), собрали схемы.
2. **Передана.** Кнопка «Передать» (дата — сегодня, можно поправить): всем схемам разом ставится статус и дата.
3. **Ответы по частям.** Заказчик может вернуть часть сегодня, часть завтра, часть послезавтра, часть — с замечаниями.
   Отмечаем результат у одной схемы или у выделенных разом; у каждой позиции своя дата ответа.
   В шапке: «15 схем · подписано 12 · замечания 2 · ждём 1 (6 дней)».
4. **Закрыта** — сама, когда у всех позиций есть результат. Остаётся в архиве (список ведомостей доски) с исходным составом
   и датами, даже если потом статусы схем поменялись.

### 6.3. Как собрать
- Из таблиц: окно отбора — шифр / раздел / статус / исполнитель («все „В работе“ по КЖ 6.1.1») → отметить галочками.
- Выделить строки прямо в таблице ИД → «В ведомость».
- Вписать вручную: шифр + захватка + вид работ (пером или клавиатурой). Есть такая схема — добавляется ссылкой.
  **Нет схемы** — приложение предлагает создать строку в таблице этого шифра (с известными полями, остальное пусто);
  нет и таблицы шифра — предлагает создать таблицу. Без подтверждения ничего не создаётся.
- Схема уже ждёт ответа в другой открытой ведомости — предупреждение.

### 6.4. На доске
Ведомость — табличка: шапка (вид, номер, кому, дата передачи, сводка ответов), строки — шифр, захватка, конструкция,
вид работ, текущий статус ИГС, результат по этой ведомости и его дата. Касание строки — показать схему в её таблице.

## 7. История
- Каждая правка статуса или даты схемы записывается: **кто** (имя, фамилия), **когда**, **было → стало**, по какой ведомости.
- Окно «История» у строки; история не стирается.
- Правки двух людей в разных строках не мешают друг другу; если двое меняют одну ячейку — остаётся последняя правка,
  обе видны в истории.

## 8. Захватки на плане
- Владимир сам раскрашивает захватки **разными цветами** — для ориентира (как сейчас). Цвет статусом не перекрашивается.
- Заливку один раз **привязывают к захватке** таблицы: выделить заливку → «Захватка» → выбрать таблицу и номер.
  Одна захватка может иметь несколько заливок (на разных листах).
- **Касание заливки → в таблице подсвечиваются строки этой захватки** (опалубка, бетон…), и наоборот:
  **касание номера захватки в таблице → подсвечивается её заливка** на плане (экран переезжает, если она не видна).
- По желанию на заливке пишется номер захватки.

## 9. Сводка и контроль
Где считать: вся доска / раздел / одна таблица. Как лист «Статистика» в Excel:
- всего схем, **сдано в ПТО / не сдано**;
- по статусам ИГС × по шифрам; по исполнителям (подрядчикам);
- Чек-лист и DWG по статусам;
- открытые ведомости: сколько схем ждут ответа и сколько дней.

**Контроль** (касание — переход к строке):
- чек-лист предъявлен, а ИГС «Не предоставлена»;
- ИГС «В работе» и дальше, а чек-лист не «Предъявлено»;
- «На подписи у заказчика» дольше 7 дней, «На подписи АН» дольше 7 дней (срок настраивается).

«Скопировать для Excel» — сводка таблицей.

## 10. Совместная работа и доступ
- Около 10 человек на объекте: **геодезисты правят, ПТО смотрит**.
- Доступ — как сейчас: **код на правку** (геодезистам) и **код «только смотреть»** (ПТО).
- Имя и фамилия обязательны для правок (в приложении уже есть; на сайте спросить один раз) — нужно для истории.
- **Правка с компьютера** через сайт (по коду на правку): таблицы, ведомости, статусы.
- iPhone и компьютер — через сайт; отдельного приложения для iOS нет.

## 11. Как это устроено (для разработчика)
- Всё хранится в доске, как остальные предметы: **таблица**, **схема** (строка), **ведомость**, **позиция ведомости**,
  **событие истории** — каждая отдельным предметом со своим номером. Поэтому правки разных строк не конфликтуют,
  а история только дописывается.
- Таблица хранит только место, размер, шифр и столбцы; строки знают свою таблицу и порядок в ней. Ведомость хранит ссылки
  на схемы (без копий), её позиции — результат и дату ответа; исходный состав — в самой ведомости.
- Сервер тот же (функция Яндекс Облака + база YDB): новые виды предметов он принимает без доработки.
  Объём: тысячи схем и событий — единицы мегабайт, в бесплатный лимит (1 ГБ) укладывается с большим запасом.
- Старым версиям приложения таблицы не видны («вид из будущей версии») — всем обновиться.

## 13. Не делаем сейчас
- Загрузку файлов (DWG, PDF, сканы) — не грузим сервер.
- Роли и тонкие права — хватает кодов «правка» / «только смотреть».
- Перекраску захваток по статусу — Владимир смотрит статусы в таблице.
- Загрузку текущего Excel — таблица Владимира ещё не готова.
- Отдельное приложение для iOS.

## 14. Открытые вопросы (ответить до шага 1–2)
1. После «Согласовано» от АН какой статус у схемы? Предложение: «В работе» (готова нести заказчику), в истории —
   «согласовано АН, дата». Или нужен отдельный статус «Согласована АН»?
2. Заказчик вернул подписанную — сразу «Сдано в ПТО», или нужен промежуточный статус «Подписана заказчиком»
   (если в ПТО отдают не в тот же день)?
3. Столбцы по умолчанию (раздел 3.2) — подходят? «Исполнитель» — это подрядчик?
4. Нужна ли выгрузка в Excel в ближайших шагах, или хватает «Скопировать для Excel» и сайта?
5. Срок «долго на подписи» — 7 дней подходит?
