# Формат доски MyScript Nebo (`.nebo`) — что выяснено

Разбор по байтам на доске Владимира (Nebo 7.4.6, Android, Document_Version 1.11), 08.11.2026.
Сам файл Владимира в репозиторий **не кладём** (рабочие чертежи). Разборщик-образец на Python —
`tools/nebo/` (`bdom.py`, `bink.py`, `tags.py`, `model.py`), запуск — на распакованном `.nebo`.

## Архив

`.nebo` — обычный zip:
- `meta.json` (`"Application": "Nebo"`), `rel.json` (страницы и картинки), `index.bdom`;
- `pages/<id>/page.bdom` — дерево страницы; `pages/<id>/ink.bink` — штрихи и метки к ним;
  `pages/<id>/meta.json` (`pageTitle` — название доски, `Type: "Raw Content"` — свободный лист),
  `pages/<id>/style.css` — стили (цвета классов, ширина пера по умолчанию 0,625 мм);
- `objects/ImageId….jpg` — картинки.

Все координаты — в **миллиметрах** (канал X/Y: единицы `mm`). Доска Владимира ~4,1 × 6 м.

## `page.bdom` — двоичное дерево (как XML)

- `BDOM` + 2 байта, затем таблица строк: `u32 длина + UTF-8`, конец таблицы — `u32 0xFF`.
- Элемент: `03 u32 имя` (или `04 03 u32 имя` + две строки: префикс, URI пространства имён),
  затем `u32 0xFF`, атрибуты `00 u32 имя тип значение`, конец атрибутов `FF`, потом дети, конец элемента `FF`.
- Типы значений: `01`,`02` строка (u32 длина + байты); `03` ссылка на строку (u32);
  `04` i64; `05` u64 (часто это **double в битах** — `struct.unpack('<d', pack('<Q', v))`);
  `06` bool (1 байт); `07` i32; `08` u32; `09` double; `0A` float.
- Дети: элементы (`03`/`04`) и текст (`01`/`02` + строка).
- Главное:
  - `page/layout/layers/layer[SNT_LAYER]/group[RootBox]/group[ActiveBlock]` — **что видно и в каком
    порядке**: `object` (картинка: `url`, `x`,`y`,`width`,`height` в мм, `transform` → `layout/transforms/transform`)
    и `strokes tag=N` (группа видимых штрихов, `N` — номер метки в `ink.bink`, вид `LAYOUT_STROKES`).
  - `layout/transforms/transform id a b c d e f` (u64 = double): x' = a·x + b·y + c, y' = d·x + e·y + f.
    Картинка на доске = её прямоугольник из `object`, пропущенный через этот transform.
  - `content/activeArea/textField*` — распознанный текст (для поиска; на доске остаётся рукопись),
    `shapeField[Shape]` — выровненные фигуры (стрелки-дуги, линии) с подписями `label`.

## `ink.bink` — штрихи

- Заголовок: `BINK`, версия 5, 2 формата каналов (X, Y, F, T в мм/мс и X, Y), разрешение 1000.
- `u32` по смещению 0x10C — **число мест под штрихи** (у Владимира 22 991).
- Дальше подряд места штрихов. Удалённый штрих — 4 байта `FF`. Номер штриха = порядковый номер места
  (первые 3301 мест удалены — номера в метках начинаются с 3301).
- Запись штриха (по первому u32 `flags`):
  - `0x80000000` — **сжатый**: `u64 время(мкс)`, `f32 x0`, `f32 y0`, `u16 промежуток между точками (мкс,
    ≈2780 = 360 точек/с)`, `u32 формат (0x0C49)`, `u32 n`, затем `n × i16 dx`, `n × i16 dy`, `n × u8` нажим (0…255).
    **Координаты: x = x0 + Σdx · 0,002 мм** (шаг 0,002 мм подобран по PDF-экспорту Владимира: при 10 px/мм
    среднее отклонение от линий PDF — 0 px; 0,001 и «u16·10⁻⁶» — неверно, проверено);
  - `0` — **как есть**: `u64 время`, `u32 формат`, `u32 n`, `n × (f32 x, f32 y)`, `n × f32 F`, `n × u32 T`;
  - `1` — **фигура**: `u64 время`, `u32 формат`, `u32 0`, `u32 флаг`, числа: формат 3111 — **линия**
    (x1,y1,x2,y2), формат 3110 — **дуга эллипса** (cx, cy, rx, ry, phi, начальный угол, угол дуги), потом `u32`.
- После штрихов — **сдвиги** групп штрихов: записи `u32 n`, `n` диапазонов, `6 × f64` матрица (как выше).
  Передвинутые надписи и картинки (их «штрих-заглушка») двигаются этим.
- Потом **метки** (теги): `u32 0`, `u32 число меток`, `u8 0`, затем каждая метка:
  `строка имя`, `u32 n`, `n` диапазонов, `строка значение`, `u32 вид`, `u32 номер`, `u32 0`
  (номер и вид — **после** метки). Имена: `LAYOUT_STROKES` (группы видимых штрихов, на них ссылается
  `page.bdom`), `.STYLE` (значение — CSS: `"color:#ff1a40ff;…"`), `pen-025/035/070` (толщина пера),
  `imageFakeContent` (штрихи-заглушки картинок — **не рисовать**), `TEXT_*`, `CHAR`, `WORD`, `DIAGRAM`, `PRIMITIVE`…
- Диапазон — 16 байт: `u32 (начальная точка << 16 | 3)`, `u32 штрих от`, `u16 флаги (0xFF05 — до конца
  штриха включительно, 0x0001 — до точки)`, `u16 конечная точка`, `u32 штрих до`.
